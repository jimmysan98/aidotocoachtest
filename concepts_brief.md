## Overview

AIDOTA is a local Windows Dota 2 assistant combining Python (`aidota/`) with an optional Rust workspace (`aidota-core/` via `aidota/rust_bridge.py`). The proposed upgrade improves tactical advice quality, latency, patch accuracy, and cost efficiency across four sequential phases without rewriting the application from scratch:

1. **Phase 1 — DeepSeek-First LLM Routing, Preemption & Streaming/TTS Hygiene:** Route requests across Tier 0 (zero-LLM deterministic timers and rules), Tier 1 (`deepseek-chat` for low-latency live voice/GSI calls), and Tier 2 (`deepseek-reasoner` for drafts, builds, and match analysis), with fallback tiers, preemption/TTL cancellation, failure isolation, and unified WebUI/CLI/voice entrypoints.
2. **Phase 2 — Asynchronous Patch Meta Synchronization:** Move OpenDota synchronization off request hot paths via disk-backed Stale-While-Revalidate (SWR) caching under a `<= 1 req/s` rate budget, splitting timeless hero/item mechanics from patch-volatile stats while keeping bundled `data/heroes.json` and `data/items.json` read-only offline baselines.
3. **Phase 4 — Canonical Map Timers, Prompt Prefix Stability & Python SSOT:** Consolidate diverging Python/JS/Rust timer and counter tables under a single canonical Python + `data/` ownership model, freeze `aidota-core/` tactical logic, and structure prompt construction to preserve DeepSeek KV prefix caching.
4. **Phase 3 — Confidence-Aware `EnemyState`, Draft/Build Adaptation & Item Validation:** Model enemy knowledge explicitly as `confirmed`, `inferred`, or `unknown`, enhance draft/mid-game build recommendations, enforce deterministic item validation against owned/removed/illegal items, and lock regressions with offline evaluation fixtures.

Phase execution order is anchored as **`Phase 1 -> Phase 2 -> Phase 4 -> Phase 3`** so routing resilience lands first, fresh patch caches feed compacted match context before prompt restructuring settles, and confidence-aware draft/item logic builds cleanly onto stabilized context and canonical item registries.

Because `self._overlay.update_hud()` (`app.py:348`) and `self._agent.process_tick()` (`app.py:353`) execute inside the same `try` block after line 344, macro timers, overlay updates, and autonomous ticks fail continuously during live matches. Fixing `_dig` immediately exposes a second collision: `MacroTimerSkill.check()` (`app.py:344`) and `MidTimersTracker` (`context.py:2464-2476`, which runs before the `autonomy_level == "off"` guard at `context.py:2484`) will both fire conflicting alerts on every tick. ### 2. Core Technical & Architectural Hazards Across Phases 1–4

#### Phase 1 — DeepSeek Routing, `deepseek-reasoner` & Preemption
- **`deepseek-reasoner` parameter & starvation hazard:** `DEFAULT_LLM_PRESETS["deepseek_r1"]` sets `max_tokens: 450` (`config.py:356`) and `_openai_chat()` clamps `min(tokens, 900)` (`coach.py:1613`). Because `deepseek-reasoner` shares `max_tokens` across hidden thinking (`reasoning_content`) and final `content`, a 450–900 token ceiling is exhausted before emitting final output, triggering false `"API вернул пустой ответ"` errors (`coach.py:1672`) or blind retries (`coach.py:625`). Sending `temperature` and 11 `COACH_TOOLS` (~800 tokens) also conflicts with reasoning endpoints or forces HTTP 400 retry hops. Furthermore, waiting `18–20s + 6s` exceeds Dota 2 Ranked All Pick turn timers (`HERO_SELECTION`).
- **Pre-LLM + Tool-Call Budget Violation:** On Tier 1 live voice (`<= 1.2s` TTFT, `<= 3.0s` total), running OpenCV `HeroVision.hero_under_cursor` + `COACH_TOOLS` (allowing up to 2 tool rounds + final HTTP call, potentially calling blocking `DotaApi.item_popularity()` with `timeout=15.0`) guarantees exceeding `3.0s` before a single spoken word arrives. `requests.Session.post(..., timeout=3.0)` also caps per-read gaps only—not wall-clock duration—and `Coach._session` is shared without thread safety.
- **TTS Preemption Gap:** `HumanTTSManager.barge_in()` (`tts.py:352`) interrupts active playback, but `_run()` (`tts.py:555`) clears `_interrupt_event` before dequeuing the next queued sentence—meaning stale queued sentences from the interrupted turn resume speaking after a critical HP alert. `Assistant._say()` (`app.py:1245`) holds `_loop()` with `wait=True`, blocking new PTT/hotkey commands from cancelling in-flight LLM requests. `ttl` is checked before synthesis (`tts.py:541`) but not again after Edge-TTS network synthesis (`10s` timeout) or Piper cold subprocess spawn (`30s` timeout).

#### Phase 2 — OpenDota SWR Meta Cache & Windows Install Permissions
- **Quota & Telemetry Reality on Anonymous Tier:** OpenDota anonymous limits (`60 req/min`, `2,000 req/day`) only allow cheap bulk fetches (`/heroStats`, `/constants/items`, `/constants/patch` = 3 requests). Per-hero `/itemPopularity` and `/matchups` across 127 heroes cost 254+ requests (~4+ minutes at 1 req/s), still omit per-role splits and item minute-timings, and return zero pick counts in the highest immortal bucket (`data/heroes.json:58-59` shows `8_pick: 0` after Valve's >8.5k MMR replay restriction).
- **Read-Only Install Path & Mutable Caches:** `installer.iss:18,33` installs into `{autopf}\AIDOTA` (`Program Files`), yet `config.py:48-54` sets `PROJECT_ROOT` to `sys.executable`'s folder and `dota_api.py:113-114` overwrites `data/heroes.json` and `data/items.json` directly—causing `PermissionError` in per-machine installs and risking corruption of offline seeds. `build_exe.py:86` also copies the entire `data/` directory into `dist/`, risking leaking developer `coach_memory.json` and `player_profile.json` into releases unless allowlisted. Meanwhile, `Coach._item_costs_cache` (`coach.py:895`) and `AidotaWebApi._*_cache` (`web_app.py:76-80`) hold process-lifetime references that ignore background refreshes, and `app.py:703` skips refresh when `snapshot_at is None`.
- **`sqlite3` Excluded from Packaging:** `AIDOTA.spec:84` excludes `sqlite3`, `pytest`, and `unittest`; any Phase 2 cache or metrics store importing `sqlite3` passes unbundled tests and crashes `AIDOTA.exe` at runtime.

#### Phase 4 — Canonical Python Truth, Map Timers & Prompt KV Caching
- **Where Duplication Actually Lives:** Static analysis confirmed `rust_bridge.compute_macro_timers_rust` and `build_advice_rust` currently have zero callers in Python (`web_app.py:589` only queries `is_rust_available()` for a header pill, while `aidota-core/src/state.rs:108` passes `&[]` enemies and `cargo test` hits Windows Application Control `os error 4551` / `0xc0e90002`). The live duplication is across Python and JS: 4 diverging timer sources (`MacroTimerSkill`, `MidTimersTracker`, `app.py:NEUTRALS_ALERT` at old `7/17/27/37/60` timings vs `context.py`'s `15/25/35/60`, and `web/app.js` JS math) and 4 overlapping counter tables (`meta_db.py`, `live_advice.py`, `coach.py:_COUNTER_HINTS/_ENEMY_ITEM_HINTS`, `context.py:_ENEMY_THREAT_HINTS`).
- **Prompt Assembly Mismatch:** `coach_brain.py:render_system_prompt()` (`L1473-1524`) packs volatile `CoachMemory.summary(turns_limit=2)`, per-tick `brief_text`, `custom_focus`, and per-query `knowledge` inside `messages[0]`; `Coach._build_messages()` trims tail history at 6000 chars (shifting byte offsets on every eviction once full); and `coach.py` routes `coach_chat` differently from 9 `_ask_llm` callers. Additionally, `tests/test_coach_smart.py:416-453` explicitly asserts that live telemetry (`ТАКТИЧЕСКИЙ БРИФ`, `ЗНАНИЯ ПО ВОПРОСУ`) appears inside `captured["system"]`. Moving dynamic telemetry to a suffix requires intentionally migrating this prompt structure and its pinned test assertions.
- **Circular Import Constraints:** `coach.py`, `coach_brain.py`, `live_advice.py`, `meta_db.py`, and `config.py` rely on function-local imports and `inspect.signature` probing (`coach.py:59`, `coach_brain.py:258`) to dodge import cycles, while `meta_db.py` mutates globals and uses unbounded `@lru_cache` at import time (`L2444, L2861, L2958`). Extracting new modules requires enforcing a downward dependency hierarchy (Pure Schemas -> Pure Domain Rules -> I/O & HTTP Adapters -> Orchestrators & UI).

#### Phase 3 — `EnemyState`, Draft/Build Logic & Item Post-Validator
- **GSI Fog-of-War Blindness:** In live Valve matchmaking, GSI omits enemy `allplayers` inventories/levels/cooldowns (`context.py:2095`), returning them only in Spectator/Lobby/Coach modes. Thus in normal matches `EnemyState.items` starts `unknown` and relies on player voice/hotkey updates or statistical match-clock inference—never silent equality with "enemy lacks item X".
- **Russian Slang vs. English `items.json` Mismatch:** `coach_brain.py:1439` tells the LLM to speak colloquial Russian (`бэкабэ`, `манта`, `эул`, `стики`, `шмотки`), whereas `data/items.json` holds English `dname`/slugs. A naive string validator causes false rejections on valid Russian advice, while retrying over LLM adds 1–3s latency on the hot voice path. Owned-item checks (`coach_brain.py:372`) also currently miss `stash*` slots and consumed `aghanims_scepter` / `aghanims_shard` buffs.
- **Compatibility Contracts (`tests/test_coach_upgrade_qa.py`):** Tests pin exact 127 hero keys in `META_HEROES_DB` and check callable legacy fallback hooks on `Coach` (`_knowledge_fallback`, `_fallback_match_analysis`, `_free_pollinations_chat`, `execute_tool`), requiring thin facade delegation if `Coach` internals move into smaller DI modules.

#### Cross-Cutting Tooling & Packaging Reality
- `requirements-dev.txt` installs only `pyinstaller` and `pyinstaller-hooks-contrib`—neither `ruff`, `mypy`, `pyright`, nor `pytest` exists in `requirements-dev.txt` or `.github/workflows/ci.yml`.
- `tools/run_tests.py` runs `unittest` and exits via `os._exit(0 | 1)` because tests leave non-daemon background threads (`GsiServer`, audio/workers) alive; running `pytest` without fixing thread teardown will hang CI.
- Running strict `mypy` and `pyright` across ~15k lines of existing dynamic GSI dicts and Win32 `ctypes` modules without module-scoped exclusions will fail immediately.
- `build_exe.py` returns exit code 1 if Inno Setup 6 (`ISCC.exe`) is absent unless an explicit PyInstaller-only mode exists.

### 3. Unresolved Architectural Forks (Author Decision Required)

Each fork below has two or three defensible engineering options with distinct trade-offs. Per EGM review rules, these are presented unranked for explicit author choice before starting `egm-draft` for Phase 1.

#### Fork A — Phase 1 Prefix Caching vs. Phase 4 Sequencing (`1 -> 2 -> 4 -> 3`)
- **Option A1 (Thin `PromptAssembly` Boundary in Phase 1):** Define `[Segment 0: Immutable System Rules/Tools | Segment 1: Match-Stable Profile/Roster | Segment 2: Ephemeral Memory/GSI/Query]` upfront in Phase 1 behind a minimal snapshot interface, and update `tests/test_coach_smart.py` telemetry-in-system assertions cleanly. *Trade-off:* Captures KV prefix cache savings during Phase 1 without changing the `1 -> 2 -> 4 -> 3` execution order; adds one modest adapter update when Phase 4 replaces raw GSI extraction. *Failure condition:* Fails if downstream Phase 3/4 prompt keys violate Segment 0/1 immutability without an automated byte-stability test.
- **Option A2 (Minimal Static-First Reorder in Phase 1, Full KV Split & Cost SLA in Phase 4):** Keep Phase 1 changes restricted to reordering static instructions ahead of dynamic text inside `render_system_prompt()` and defer strict KV prefix-cache hit targets (`prompt_cache_hit_tokens`) and sliding-window epoch truncation to Phase 4. *Trade-off:* Smallest Phase 1 diff; accepts near-zero DeepSeek prefix hits between Phase 1 and Phase 4. *Failure condition:* Fails if `$0.01–$0.03`/match is evaluated as a hard Phase 1 exit gate.

#### Fork B — Tier 1 Live Voice Transport & TTS Coupling
- **Option B1 (SSE Clause Streaming + Pre-Warmed Async Edge/Piper + Preemptible Fillers):** Convert `_openai_chat` live calls to SSE streaming with a monotonic wall-clock deadline (`3.0s`), emit complete Russian clauses (handling abbreviations `ур.`, `поз.`, decimal timings) directly into a non-blocking producer-consumer TTS pipeline, abort the HTTP stream once sentence limits trigger, and require banning `COACH_TOOLS` from the combat hot path. *Trade-off:* Lowest possible first-audio delay (`<= 1.2s`) and saves trailing output tokens; higher parser/concurrency surface and must buffer short item clauses if post-validation runs before speech. *Failure condition:* Fails if incremental clause splitting chops abbreviations mid-word or TTS subprocess restarts stutter between short clauses.
- **Option B2 (Non-Streaming Fast `deepseek-chat` + Wall-Clock Deadline + Async TTS Queue):** Keep non-streaming completions for short 60–120 token voice replies under strict `(connect=1.0s, read=2.0s)` + monotonic `3.0s` total cap (banning `COACH_TOOLS` on hot path), run `sanitize_answer()` + validation atomically on the whole reply, enqueue into non-blocking TTS (`wait=False`) stamped with `generation_id`, and retain `0.8s` preemptible fillers. *Trade-off:* Eliminates SSE clause-chunking and partial-sentence validation hazards with minimal diff; TTFT to audio starts after 60–120 token generation completes (~0.7–1.6s depending on API load). *Failure condition:* Fails `<= 1.2s` TTFT SLA on multi-sentence replies if upstream API exceeds ~8–12 tokens/s latency variance.

#### Fork C — Tier 2 `deepseek-reasoner` Token Ceiling & Ranked Draft Clock
- **Option C1 (Uncap API `max_tokens >= 4096` + Dual Draft/Offline Deadlines):** Keep `400–800` token brevity limits via prompt instructions and UI formatting, raise `deepseek-reasoner` API `max_tokens`/`max_completion_tokens` ceiling above reasoning demand (`>= 4096`), run live `draft`/`pick_advice` under an `8–10s` deadline (falling back to `deepseek-chat` before Ranked pick clock expires) while keeping `18–20s` exclusively for `STRATEGY_TIME`, death downtime (`>= 15s`), and post-match chat/review. *Trade-off:* Prevents `reasoning_content` from starving `content` and aligns with Ranked Pick timers. *Failure condition:* Raises Tier 2 per-call output cost if unbounded reasoning runs frequently on minor chat questions.
- **Option C2 (`deepseek-reasoner` Strictly for Non-Blocking Chat/Review/Strategy Memo + `deepseek-chat` for Urgent Pick):** Reserve `deepseek-reasoner` solely for async Chat UI (`Cancel` / `Switch to Fast` button), background Strategy Memos during death/strategy phases, and post-match `analyze_match` (`18–20s`), while interactive live Draft commands use `deepseek-chat` (`<= 6s`) + deterministic `recommend_picks`. *Trade-off:* Guarantees live pick responsiveness; exchanges deep multi-step pick reasoning during active countdown for predictable latency. *Failure condition:* Fails user expectation if explicit Draft button expects `deepseek-reasoner` chain-of-thought.

#### Fork D — Phase 2 OpenDota Anonymous Scope & Config Complexity
- **Option D1 (Bulk-3 + Lazy Per-Match 10-Hero SWR Cache in AppData):** Bundle `data/heroes.json` & `data/items.json` read-only in install dirs, write SWR cache files (`/heroStats`, `/constants/items`, `/constants/patch` + lazy `/itemPopularity` & `/matchups` limited strictly to the 10 active match heroes, cached 24–72h under a `<= 1 req/s` limiter + persisted `429` backoff) into user-writable `%LOCALAPPDATA%\AIDOTA\` (or local workspace `.cache/` in dev mode), and expose a single `cache_version` invalidator to `Coach` and `AidotaWebApi`. Omit unused STRATZ fields until actually implemented. *Trade-off:* Minimizes daily quota (~1–2% of anonymous 2,000 req/day) while refreshing actual matchup/item stats for active games and respecting read-only `Program Files`. *Failure condition:* First 10–20s of an unseen enemy hero on a brand-new patch still relies on prior snapshot or static fallback until trickle fetch completes.
- **Option D2 (Bulk `/heroStats` + `/constants/items` Background Refresh Only):** Keep anonymous sync strictly to bulk endpoints (2–3 requests total every 24–72h) written atomically to writable AppData cache with explicit invalidation hooks, omitting per-hero `/itemPopularity`/`matchups` SWR orchestration and optional STRATZ config entirely. *Trade-off:* Zero quota risk and minimal complexity; omits dynamic patch item-popularity shifts per hero. *Failure condition:* Cannot reflect sudden patch item-build shifts unless `data/heroes.json` / `meta_db` receives manual updates.

#### Fork E — Phase 3 `EnemyState`, Item Validation & Voice Grounding
- **Option E1 (Tri-State `EnemyState` + Bidirectional Alias/Rule Registry + Deterministic Rewrite):** Track `confirmed | inferred | unknown` per enemy hero via `draft`/spectator `allplayers` + clock-based match timing + voice/UI callouts (excluding continuous CV from MVP), build one shared Cyrillic-slang <-> slug/component/consumed-buff registry (checking `stash*` + `aghanims_scepter`/`shard` + `_UPGRADE_EQUIVALENTS`), validate structured draft/build DTOs and short voice output post-generation, and on rejection apply a deterministic Tier 0 replacement without LLM retries. Lock regressions with deterministic offline test cases (`golden_evals` inside `tests/`). *Trade-off:* Eliminates invisible hallucinated/already-owned item calls without adding retry latency; requires maintaining Cyrillic Dota item aliases alongside `items.json`. *Failure condition:* False-positives reject colloquial speech if alias coverage omits new/slang item phrases.
- **Option E2 (Upstream Prompt Grounding + Structured Card Validation Only):** Reuse existing `build_brief` `enemy_picks` vs `enemy_items`, inject explicit `"Предметы врагов: не видны — не угадывай"` guard when hidden, run deterministic ownership/existence validation only on structured UI/TTS item recommendation DTOs (`live_advice.build_item_advice`, Draft picks) without Cyrillic regex validation on free-form LLM chat prose, and expand `tests/` `unittest` fixtures rather than creating a separate eval framework. *Trade-off:* Zero false-rejection risk on Russian speech; leaves free-form voice LLM replies subject only to temperature clamping (`<= 0.35`) and prompt rules. *Failure condition:* Hallucinated item mentions in free-form conversational chat replies pass unblocked.

#### Fork F — Canonical Rule Storage Format (`data/*.json` vs. Pure Python Modules)
- **Option F1 (Declarative `data/*.json` Schemas + Thin Evaluators):** Extract macro schedules (including 7/15/25/35/60 neutral tiers, Turbo scaling, bounty, day/night), timeless hero mechanics, and counter-item tables into validated `data/*.json` assets bundled in `AIDOTA.spec`, deleting duplicate Python tables (`_COUNTER_HINTS`, `_ENEMY_THREAT_HINTS`, `MidTimersTracker`, JS timer math) and freezing `aidota-core/`. *Trade-off:* Zero code edits needed to update patch/timer numbers and easily consumed by tests/UI; adds schema loader/validator code and requires updating `AIDOTA.spec` / `build_exe.py`. *Failure condition:* Frozen PyInstaller builds fail if new `data/*.json` assets miss allowlist entries in `build_exe.py` / `installer.iss`.
- **Option F2 (Consolidated Pure-Python Canonical Modules):** Keep domain tables inside unified Python modules (`meta_db.py` + `live_advice.py` + unified `skills/macro_timer.py` with bounty & day/night added), delete redundant inline dicts in `coach.py` / `context.py` / `app.py` / `app.js`, and freeze `aidota-core/`. *Trade-off:* Zero new schema DSL or packaging manifest churn while resolving all internal Python/JS duplication; still requires editing Python dicts when mechanics/timers change across patches. *Failure condition:* Fails if non-code patch data updates are strictly expected without code edits.

#### Fork G — Quality Gates, CI Runner & Observability Surface
- **Option G1 (Incremental Hardened Gates + JSONL Turn Telemetry):** Pin `ruff`, `mypy`, and `pytest` (+ `pytest-timeout`) in `requirements-dev.txt`; configure `mypy` strictly on newly created/refactored Phase 1–4 modules first (leaving untouched legacy Win32/pywebview files baseline-ignored); fix leaking daemon threads in test teardowns instead of relying solely on `os._exit`; add `--pyinstaller-only` smoke verification in `ci.yml`; and write redacted structured `metrics.jsonl` (`turn_id`, `tier`, `ttft_ms`, `cache_hit_tokens`, `outcome`) separately from human-readable `logs/aidota.log`. *Trade-off:* Real CI enforcement of types, leaks, cache hit ratios, and latency regressions; moderate upfront cleanup on existing test suites. *Failure condition:* Blocked if legacy Win32 tests cannot cleanly join background threads without deeper fixture rewrites.

## Goals vs. Non-Goals

### Goals
- **Deterministic Zero-LLM Hot Rules (Tier 0):** Answer map timers (bounty, water, power, wisdom, lotus, catapults, stack/pull, day/night, Tormentor, Roshan, neutral tiers), HP/mana/TP/buyback alerts, exact cooldowns, and deterministic counter items locally with zero LLM calls and zero latency spikes.
- **Resilient DeepSeek-First Tiered Routing (Phase 1):** Use `deepseek-chat` for low-latency live tactical responses and `deepseek-reasoner` strictly on non-combat strategic intents (draft, match plan, tavern build rebuild, match review, deep chat) while isolating `reasoning_content` debug-only, unifying `Coach` / `WebApp` / CLI routes, preempting stale speech cleanly, and falling back deterministically without hanging on Pollinations during combat.
- **Non-Blocking Patch Metadata Sync (Phase 2):** Keep live queries 100% free of synchronous OpenDota calls; refresh patch baselines via disk-backed SWR in a user-writable location with rate-limit backoff and cache invalidation across UI and `Coach`.
- **Single Canonical Source of Truth & Prompt Hygiene (Phase 4):** Eliminate multi-module rule/timer drift inside Python and JS, freeze `aidota-core/` tactical duplication cleanly, separate immutable match/system prompt segments from volatile turn state, and repair existing `_dig` / WebUI timer bugs.
- **Honest Enemy Modeling & Safe Item Recommendations (Phase 3):** Never treat unobserved fog-of-war enemy state as confirmed absence or confirmed purchase; prevent hallucinated, removed, or already-owned item advice via deterministic checks grounded in `data/items.json` and player inventory/buffs.
- **Security & Packaging Readiness:** Ensure secret redaction across logs and settings IPC, atomic config/cache persistence safe in per-machine Windows `Program Files` installs, zero `sqlite3` runtime imports unless `AIDOTA.spec` changes, and zero developer state leakage into `AIDOTA_Setup.exe`.

### Non-Goals
- **No Rewrite From Scratch:** Retain incremental module structure, `unittest`/`Coach` facade hooks (`_knowledge_fallback`, `_fallback_match_analysis`, `_free_pollinations_chat`, `execute_tool`), and WebView/Tray/Overlay UX architecture.
- **No Live Ranked Enemy Telemetry Bypass:** Do not introduce memory reading, game-client injection, or always-on screen OCR to recover fog-of-war enemy items in standard matchmaking.
- **No Unapproved Scope Additions or Broken Builds:** Do not ship STRATZ API keys/calls, unsigned Rust DLL runtime dependencies on Windows App Control hosts, or UI chrome claiming inactive `"Rust Core"` acceleration.

## Alternatives Weighed

1. **Rewrite Core Runtime in Rust (`aidota-core`) First:** Rejected by author. `cargo test` fails locally with Windows Application Control (`os error 4551`), unsigned `aidota_rust.dll` fails loading (`0xc0e90002`), and `rust_bridge` timer/advice functions already have zero Python callers while lacking enemy state (`&[]`). Pure Python + bundled data satisfies sub-millisecond timer/counter checks without native signing overhead.
2. **Use `deepseek-reasoner` as a Single Unified Model Everywhere:** Rejected by author. Chain-of-thought latency (15–20s+) stalls combat voice responses and violates Ranked pick/call responsiveness; isolating `deepseek-chat` vs `deepseek-reasoner` preserves reasoning depth only where match time allows.
3. **Full Multi-Provider Catalog (`Pollinations` + 15 Competing Presets) in Default Flow:** Rejected by author for active keyed setups. Pollinations exhibits unpredictable queue latency (up to 25s) and lacks compatible tool/caching guarantees; keep an OpenAI-compatible adapter for optional user endpoints (OpenRouter, Gemini, Ollama) while separating zero-key mode cleanly from keyed DeepSeek execution.
4. **SQLite Disk Store for Phase 2 Meta Cache & Phase 3 Evals:** Descoped unless `AIDOTA.spec` is deliberately changed. `AIDOTA.spec:84` excludes `sqlite3`, guaranteeing `ModuleNotFoundError` in `AIDOTA.exe`, whereas `CoachMemory._save` (`coach_memory.py:95-111`) already provides an atomic temp-file + `os.fsync` + `os.replace` pattern suitable for versioned JSON/NDJSON caches.
5. **Reordering Execution to `4 -> 1 -> 2 -> 3`:** Weighed against author preference `1 -> 2 -> 4 -> 3`. Keeping `1 -> 2 -> 4 -> 3` delivers immediate fixes (`_dig`, WebUI Doctor/Chat unblocking, Tier 0/1/2 routing, preemption) in Phase 1; Fork A settles how much of the prompt prefix boundary enters Phase 1 cleanly vs Phase 4.
